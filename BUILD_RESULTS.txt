6. REAL DEFECTS FOUND BY THIS VERIFICATION — all fixed, all re-verified
================================================================================

Running the commands locally surfaced four genuine bugs that would have
failed the build on a networked machine too. They were fixed before
packaging, and section 5 was re-run clean afterwards.

DEFECT 1 — 319 errors — src/i18n/vi.ts could never compile
  Cause : Dict was 'typeof en' where en is 'as const', making every
          English string a LITERAL type. 'vi: Dict' therefore demanded the
          Vietnamese text be identical to the English text.
          e.g. Type '"Tiếp tục"' is not assignable to type '"Continue"'
  Fix   : added a Widen<T> mapped type in src/i18n/en.ts. Key structure is
          still enforced (a missing key fails the build) but string VALUES
          are free to differ — which is the entire point of a locale.
  Verify: 319 -> 0 errors. Both locales now typecheck under --strict.

DEFECT 2 — 2 errors — unused imports
  Cause : 'Money' and 'RECEIPTS' imported but never used in
          src/features/deductions/screens.tsx. Fails under noUnusedLocals.
  Fix   : removed.

DEFECT 3 — 1 error — no ambient declaration for CSS imports
  Cause : src/main.tsx does "import './index.css'" with no declaration.
          TS2882: Cannot find module or type declarations for side-effect import.
  Fix   : added src/vite-env.d.ts with the Vite client reference.

DEFECT 4 — 1 error — test file used process.exit without node types
  Cause : TS2591: Cannot find name 'process'.
  Fix   : added @types/node to devDependencies and to tsconfig types.

  package-lock.json — STILL NOT INCLUDED, AND I WILL NOT FABRICATE ONE
    A lockfile records resolved tarball URLs and SHA-512 integrity hashes
    obtained from the registry. Without network access those values cannot be
    computed. A hand-written lockfile would carry either absent or invented
    integrity hashes, which is worse than no lockfile: npm would either reject
    it or, if hashes were omitted, silently resolve a different tree while
    LOOKING reproducible. That is a supply-chain hazard, not a formality.

    What has been done instead, so the first install is as close to
    deterministic as is possible offline:
      - every version pinned exactly, no ranges anywhere
      - .npmrc enforcing save-exact and engine-strict
      - engines.node >= 20.19.0 declared

    REQUIRED NEXT STEP (one command, on a networked machine):
      npm install && git add package-lock.json && git commit -m "chore: lockfile"
    With exact pins, that lockfile is reproducible by anyone who runs the same
    command against the same registry.
