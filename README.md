# Sổ Sạch — Phase 2 Functional Prototype

Bilingual tax automation and business-finance organization software for
Vietnamese restaurant and nail salon owners.

> **We organize your business finances and help you prepare for tax time.**
> We do not provide legal, accounting, or professional tax advice.

Built against the accepted Phase 1 architecture, types, and permission matrix.

---

## Setup

```bash
npm install
npm run dev          # http://localhost:5173
npm run typecheck
npm run test
npm run build
```

Requires Node 20+. `npm install` needs network access.

### Reviewing without installing

The repo ships a pre-rendered static preview so the screens can be reviewed
offline, with no toolchain:

```bash
open preview/home-vi.html
```

Twenty routes are pre-rendered. Screenshots are in `screenshots/`. The preview
is generated by `tools/ssr.mjs` and is **not** part of the product — the real
app runs through Vite.

## Product boundaries enforced in code

**AI suggests; the customer confirms.** `Transaction.suggested` and
`Transaction.confirmed` are separate fields — a suggestion structurally cannot
become a confirmed figure. `isExportable()` requires `confirmed`.

**Bulk confirm is not a shortcut.** It emits one confirm per row so the audit
trail stays per-record.

**Sharing is scoped and expiring.** `SharingGrant.expiresAt` is non-nullable;
a permanent grant is not expressible.

**Only the owner confirms and grants.** Managers and bookkeepers prepare.

**Completeness is stated before export**, on the screen, not buried.

**Numbers come from the engine.** The quarterly screen renders the engine's
trace verbatim, with `[unverified]` tags visible to the customer.

## Known limitations

1. **No live data.** All adapters are mocked. Banking, OCR, storage, payroll,
   and notification services are fixtures only.
2. **Tax engine not expanded**, per instruction. The quarterly screen renders
   a fixture shaped exactly like engine output. Wiring is a Phase 3 task.
3. **Vietnamese copy needs native review.** Drafted here in the familiar
   register (anh/chị). Trade vocabulary — "tiền thuê ghế" for booth rent —
   must be confirmed by a speaker who knows these businesses. This is
   founder decision #6 and #7 from the architecture checkpoint.
4. **`@types/react` unavailable offline**, so a full `npm run typecheck` could
   not be run in this environment. Non-React modules (types, permissions,
   fixtures, both locale files) type-check clean under `--strict`, and every
   `.tsx` transpiles with zero syntax errors. Run `npm install && npm run
   typecheck` to verify the TSX against real React types.
5. **`preview.css` is a hand-generated Tailwind subset** used only for offline
   rendering. Production uses real Tailwind via `tailwind.config.js`. If you
   add utilities, regenerate with `node tools/gen-css.cjs` or just run Vite.
6. **Not yet built:** alerts screen, messages, settings, security, billing,
   admin shell, contractor/W-9 tracker, tip tracker, sales-tax tracker,
   bulk-categorization detail view, transaction detail, receipt detail.
   Routes and types exist; screens are Phase 3.
7. **Accessibility not formally audited.** Semantic HTML, keyboard-reachable
   controls, `aria-label`s, status-icon-plus-text, and visible focus rings are
   in place. An axe pass and screen-reader review are Phase 5.
8. **Screens are seeded from fixtures directly** rather than through service
   adapters. The adapter layer is specified but not yet wired.
9. **Eight tax questions remain open** — see ARCHITECTURE §20. Most blocking:
   whether nail *services* are subject to Virginia sales tax.

## Structure

```
src/
  app/          App shell, router abstraction
  components/   UI primitives and patterns
  layouts/      Marketing, Auth, Onboarding, App shells
  features/     Screens, grouped by domain
  i18n/         en.ts, vi.ts, provider — equal locales
  mocks/        Deterministic seeded fixtures
  security/     Permission matrix, masking, redaction
  types/        Domain model
  tests/        Suite
tools/          Offline preview generation (not shipped)
preview/        Pre-rendered HTML (not shipped)
screenshots/    Desktop and mobile
```

Screens never import `react-router-dom` — they use `useNav()` and `<Link>` from
`app/router.tsx`. `main.tsx` bridges the real router to that abstraction.
